# mb-generation Specification

## Purpose
Defines how `mb gen` turns each plugin's single hand-edited source into the manifests, marketplaces, vendored kit and docs that hosts read.

## Requirements

### Requirement: MB-GEN-001 Single source per plugin
Each plugin SHALL have exactly one hand-edited manifest source, `plugin.src.json`, and every manifest a host reads SHALL be generated from it.

#### Scenario: Manifests come from the source
- **WHEN** `plugin.src.json` changes and `./mb gen` runs
- **THEN** both host manifests of that plugin reflect the change (test tools/tests/gen.test.mjs)

### Requirement: MB-GEN-002 Claude plugin manifest
`mb gen` SHALL write `<plugin>/.claude-plugin/plugin.json` with the keys author, description, homepage, keywords, license, name, repository and version, omitting optional fields that the source lacks.

#### Scenario: Claude manifest shape
- **WHEN** `./mb gen` runs on a plugin with all optional fields
- **THEN** the Claude manifest matches the golden file and passes `claude plugin validate --strict` (test tools/tests/gen.test.mjs)

### Requirement: MB-GEN-003 Codex plugin manifest
`mb gen` SHALL write `<plugin>/.codex-plugin/plugin.json` with the same key set as the Claude manifest and SHALL NOT emit `interface` or `skills`.

#### Scenario: Codex manifest shape
- **WHEN** `./mb gen` runs on a plugin
- **THEN** the Codex manifest has the Claude key set and no `interface` or `skills` key (test tools/tests/gen.test.mjs)

### Requirement: MB-GEN-004 Claude marketplace
`mb gen` SHALL write `.claude-plugin/marketplace.json` with `metadata.description`, `name`, `owner` and one `plugins` entry per plugin sorted by name, and SHALL NOT copy plugin versions into the entries.

#### Scenario: Claude marketplace lists plugins
- **WHEN** `./mb gen` runs on a repo with two plugins
- **THEN** the Claude marketplace lists both, sorted, without versions (test tools/tests/gen.test.mjs)

### Requirement: MB-GEN-005 Codex marketplace
`mb gen` SHALL write `.agents/plugins/marketplace.json` with `interface.displayName`, `name` and one entry per plugin carrying `category`, `policy` and a local `source.path`.

#### Scenario: Codex marketplace lists plugins
- **WHEN** `./mb gen` runs on a repo with two plugins
- **THEN** the Codex marketplace lists both with policy and local source paths (test tools/tests/gen.test.mjs)

### Requirement: MB-GEN-006 Version stamping
The generated version of a configurable plugin SHALL be its source version plus `+mb.<sha8>`, where sha8 is taken over its vendored `_mb/` trees; other plugins SHALL use the source version unchanged.

#### Scenario: Only affected plugins are re-versioned
- **WHEN** the kit or policy changes and `./mb gen` runs
- **THEN** only configurable plugins get a new `+mb.` suffix (test tools/tests/gen.test.mjs)

### Requirement: MB-GEN-007 Kit vendoring
`mb gen` SHALL copy the kit, the policy files and a `kit.json` into `skills/<s>/_mb/` of every skill of a configurable plugin, with only `kit.json#skill` differing between skills of one plugin.

#### Scenario: Every skill of a configurable plugin gets the kit
- **WHEN** a plugin has `config.defaults.json` and two skills
- **THEN** both skills get a byte-identical kit and differ only in `kit.json#skill` (test tools/tests/gen.test.mjs)

### Requirement: MB-GEN-008 Deterministic output
`mb gen` SHALL write canonical JSON (sorted keys, 2-space indent, LF, trailing newline) and SHALL produce no diff when run twice.

#### Scenario: Second run changes nothing
- **WHEN** `./mb gen` runs twice
- **THEN** the second run changes no file (test tools/tests/gen.test.mjs)

### Requirement: MB-GEN-009 Drift check
`mb gen --check` SHALL build every generated artifact in memory and exit 1, naming each differing file, when any committed generated byte differs.

#### Scenario: One edited byte is caught
- **WHEN** one byte of a generated file is edited and `./mb gen --check` runs
- **THEN** it exits 1 and names that file (test tools/tests/gen.test.mjs)
